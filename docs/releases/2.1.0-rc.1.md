# LABIOS 2.1.0-rc.1 release candidate

**Prepared:** 2026-08-26  
**Proposed tag:** `v2.1.0-rc.1`  
**Deployment claim:** single-host Docker Compose reference topology

## Why 2.1

This release changes more than implementation detail. LABIOS now treats a label
as a versioned, validated I/O program with a mutable execution residual. Typed
resources, durable delivery, executable pipelines, real scheduling inputs,
owning completion APIs, Python bindings, and MCP ingress all converge on that
model. The scope is therefore a 2.1 minor release rather than another 2.0 patch.

This checkpoint is an RC because final-plan gates remain open: catalog-backed
cross-process channels/workspaces, MCP workspace knowledge, a scientific
frontend/equivalence demonstration, and a valid independent trace-guided
experiment. None is implied by this candidate.

## Candidate highlights

- Label I/O IR v1 and registry protocol v2.
- Verified FlatBuffers ingress and stable validation categories.
- Durable JetStream labels with catalog recovery and parking.
- File/SQLite/optional user-Redis execution and one-worker registered pipelines.
- Four scheduling policy families over typed feasibility inputs with replayable
  placement evidence.
- Owning C++/C/Python asynchronous lifecycle and completion APIs.
- MCP core I/O through public Label I/O, with no direct plumbing bypass.
- Reproducible single-host Compose golden paths and explicit limitations.

See [the changelog](../../CHANGELOG.md) for compatibility breaks and the full
scope.

The optional characterization failures are not converted into correctness or
performance conclusions. The 100 MiB case measured approximately 2.16 MiB/s
write and 1.85 MiB/s read on the rehearsal host; this candidate makes no
throughput claim and retains the valid independent experiment as a final-release
gate.

The four catalog recovery cases must run with the dispatcher stopped because
they deliberately create globally discoverable queued records and then inspect
them. Running those fixtures beside a live dispatcher creates a test-harness
consumer race, not a supported test mode.
